# TARGET PRO (бывший LeadBoost) — контекст проекта

Лендинг бренда TARGET PRO (Nijat, Баку). Основная услуга — таргетированная
реклама, дополнительная — создание сайтов. Клиенты преимущественно в
Казахстане, цены в USD.

**Ребрендинг (ноябрь 2026):** имя LeadBoost больше не используется, бренд
называется TARGET PRO, домен targetpro.studio (подключить в Vercel). Логотип
только надпись: TARGET тёмным на жёлтой плашке, PRO тёмным на светлом и
белым на тёмном (шрифт Kumbh Sans 800, вшит в SVG как контуры), файлы
`img/logo.svg` (светлая тема) и `img/logo-dark.svg` (тёмная). Правила логотипа и
что нельзя (инициалы TP, T на жёлтом как у Т-Банка, мишень как у Target) в
документе проекта `claude/target-pro-logo.md`. Ники соцсетей в config.js пока
старые (@leadboost_agency): менять, когда владелец переименует аккаунты.
Название репозитория и пакета `leadboost` оставлены как есть.

## Дизайн: светлая основа брендбука и тёмная тема (с ноября 2026)

Сайт оформлен по брендбуку TARGET PRO (палитра 02 «светлая основа»:
белая бумага, чёрный текст, жёлтый маркер), ссылка на брендбук в
документе проекта `claude/target-pro-logo.md`. Раскладка и компоненты те
же, что были в тёмном стиле каруселей (октябрь 2026, Figma-файл
d395dvUXTP40ey4jbBBLfR); тот тёмный вид остался как тёмная тема.

**Темы.** По умолчанию светлая. Переключатель в шапке рядом с языком
(`ThemeToggle` в App.jsx: луна в светлой, солнце в тёмной), на телефоне
ещё строка «Тёмная тема» с ползунком в меню. Выбор хранится в
localStorage `tp-theme` (единственное, что сайт туда пишет). Скрипт в
`<head>` index.html ставит `html[data-theme="dark"]` до отрисовки, чтобы
не мигало белым; он же меняет meta theme-color. В React тема через
`useTheme`/`setTheme` (interactions.jsx, useSyncExternalStore, на сервере
всегда "light"), поэтому hydration не расходится. Всё, что зависит от
темы визуально (иконка, логотип, ползунок), переключает CSS по
`html[data-theme]`, а не JS. Тему по системной настройке не берём
специально: лицо бренда светлое.

**Токены** (`.cl-root` светлая, `html[data-theme="dark"] .cl-root` тёмная):
- Светлая: фон `#FAFAF7` с сеткой 60px (`--grid`, чёрный 5%), плитки
  `#FFFFFF`, внутренние блоки `#F3F3EE`, обводка 2px `#E3E4DF`, текст
  `#0F1216`, тело `#2E353D`, вторичный `#5C6570`, тусклый `#6B7480`
  (контраст на бумаге 4.5 и выше).
- Тёмная: прежние `#0F1216`, `#151A21`, `#232A33`, `#1E242D`, тело
  `#D3D9E2`, вторичный `#AEB7C3`, тусклый `#8A94A1`.
- `--y` жёлтый `#F0E60D` только как заливка (мазок `.hl`, плитка
  «Твоей ниши нет?», верхняя лента под первым экраном, полоса мест в
  «Контакте», галочка «Подходит, если»), текст
  на нём всегда `#0F1216`. **Жёлтый текст на светлом нельзя** (контраст
  1.25): для цветного текста, обводок, иконок и полосы прокрутки есть
  `--accent`, он чёрный в светлой теме и жёлтый в тёмной.
- Кнопки `--btn-*`: в светлой чёрные с белым текстом, в тёмной жёлтые;
  при наведении жёлтые с тёмным текстом в обеих.
- Радиус 28 (на телефоне 22). Тени мягкие нейтральные (`--shadow-*`).
- Шрифты: **Oswald Bold** капсом (заголовки, крупные цифры, кнопки),
  **Inter Medium** (текст), **JetBrains Mono Bold** (лейблы `ТЕКСТ`,
  бейджи). Свои файлы через пакеты `@fontsource/*`
  (импорт в main.jsx), без Google Fonts: быстрее и без внешних запросов.
- Заголовок секции = компонент `<Heading pre mark>`: строки `pre` цветом текста,
  последняя строка `mark` на жёлтой плашке (`.hl`). **Мазок только на
  четырёх экранах:** первый экран, «Кейсы из моего кабинета Meta»,
  «Тарифы от $350 в месяц», «Напиши, отвечу сам в течение дня» (ноябрь
  2026: мазков было 13, выделение перестало выделять). У остальных
  заголовков `mark` нет. Между строками `Heading` ставит пробел: на экране
  он не виден (строки блочные), а поисковики и диктор без него читали
  слова слитно. Мазок не должен переноситься: на узких телефонах
  (меньше ~358px) заголовки мельче (`.hd` в styles.css). Плашка обрезана по
  высоте как на каруселях: 13px над капителью и 10px под базовой линией
  при 104px (в CSS это 1.031em, смещение 0.258em). Перед строкой с плашкой
  отступ 0.16em, чтобы строки не слипались.
- С 11 ноября 2026 плашка на сайте это мазок маркера, а не ровный
  прямоугольник (владелец: «слишком аккуратно, должно выглядеть
  натурально», потом «недостаточно заметно, что это маркер»). Три фоновые
  SVG-картинки: начало 0.42em (скос, густая краска), середина (тянется по
  длине слова: заметно неровные края, наклон, прерывистые светлые полосы
  от нажатия, краска гуще у краёв) и конец 0.42em (краска кончается,
  мазок расходится на тонкие острые полоски разной длины). Картинка
  выше прямой плашки (1.09em от 0.23em), края гуляют вокруг её границ.
  В светлой теме `mix-blend-mode: multiply`: сквозь жёлтый видна сетка
  бумаги, как у настоящего маркера (в тёмной нет, жёлтый стал бы
  грязным). Начало
  и конец не растягиваются, поэтому мазок одинаково выглядит на коротком
  «сам» и на длинном «тапсырманы әкеліңіз». Три варианта мазка `.hl-a/b/c`,
  `Mark` выбирает вариант по тексту (хэш, одинаково на сервере и в
  браузере). На переносе каждая строка получает свой мазок. Появление:
  `--hlp` (через `@property`) от 0 до 1, мазок тянется слева направо; без
  `@property` просто появляется. Картинки собирает `scripts/hl-marker.mjs`
  (печатает CSS, его вставляют в styles.css вместо блока `.hl-a/b/c`).
  Логотип не трогали: там плашка прямая, это правило логотипа. Картинки
  превью ссылок `img/og/*.jpg` с ноября 2026 тоже с мазком (см. SEO).
- `<SecLabel>`: моно капсом `ТЕКСТ`, **только внутри плиток** (`--lbl-sm`:
  «Из моего кабинета Meta», название тарифа, подписи скринов, колонки
  подвала). Над заголовками секций подписей капсом нет: они повторяли меню
  и вместе с мазком делали все разделы одинаковыми (ноябрь 2026). Без «//»
  перед текстом: владелец убрал их 11 ноября 2026, они придавали сайту
  вид сделанного ИИ. Не возвращать ни то, ни другое.
- Первый экран: бенто-сетка (заголовок, реальная цифра из кабинета со
  скрином, 240+ кампаний, ROAS 310%), над ней справа только статус «на
  связи». Заголовок из фактов: «Таргет в Instagram и Facebook для бизнеса
  в Казахстане и СНГ», мазок на «в Казахстане и СНГ». Размер заголовка
  считается от ширины плитки (`container-type` у `.hero-main`, `10cqi`, не
  больше 66px): самая длинная строка на трёх языках до 9,4em, поэтому
  влезает на любой ширине, и мазок не переносится. Меняя заголовок, строки
  держать такой же длины. Угловых жёлтых скобок больше нет (в брендбуке их
  нет, на светлом жёлтые линии не читаются).
- Под первым экраном две перекрещённые ленты, как на каруселях (владелец
  вернул их 11 ноября 2026 вместо одной спокойной строки, это его
  исключение из брендбука только для сайта): жёлтая сверху
  (`TAPE_WHAT`, rotate −3°), белая под ней (`TAPE_WHERE`, rotate 2.5°, едет
  в обратную сторону), слова Oswald тёмным, между ними крестики. Обе едут
  от скролла (`useVelocityMarquee`). Белая лента в тёмной теме `#E9EDF2`, в
  светлой `#FFFFFF` с серыми краями 2px (`--tape2-*`), иначе сливается с
  бумагой. Чёрной её не делать: жёлтая с чёрной это сигнальная полоса,
  её брендбук запрещает.
- Футер: три колонки (ссылки, связь, статус) и «TARGET PRO ├────┤ НАПИСАТЬ →»
  как подпись на каруселях. Лозунга «Ясность, которая продаёт» и строки
  «Реклама, сайты, аналитика» больше нет.
- Кнопки «Наверх» в подвале нет (владелец попросил перенести, октябрь
  2026): на компьютере `.to-top` висит над боковой кнопкой WhatsApp по её
  центру, на телефоне `.m-up` сидит внутри нижней панели `.m-cta` и висит
  над её правым краем (так она над панелью при любой её высоте). В нижней
  панели на телефоне только кнопка «Написать в WhatsApp»: счётчик мест
  там висел всё время и читался как продажный трюк, места показаны один
  раз в «Контакте».
  Появляются и прячутся вместе с ними (`FloatingCta`). Чтобы кнопки внизу
  страницы ничего не закрывали: на компьютере у `.brand-line` и
  `.footer-base` правый отступ, пока поле справа уже 100px; на телефоне
  строки `.footer-base` столбиком слева.
- Значки WhatsApp, Telegram и Instagram на всех кнопках связи (первый
  экран, меню на телефоне, «Контакт», «Вопросы», плавающие кнопки):
  официальные формы (прислал владелец), одноцветные цветом текста кнопки:
  белые на чёрной, тёмные на жёлтой и на светлой, при наведении вместе с
  текстом (в обеих темах). Файлы
  `img/icons/social/*.webp` (96×96, белый на прозрачном) задают только
  форму, `SocialIcon` (widgets.jsx) красит их CSS-маской (`.soc-ic`,
  currentColor), на кнопке 20px. Цветные значки на жёлтой кнопке
  смотрелись плохо, владелец выбрал одноцветные (октябрь 2026). В подвале
  («СВЯЗЬ», `.f-social`) те же значки 18px перед названием: WhatsApp,
  Telegram, Instagram, TikTok, Threads. TikTok и Threads (оба
  @leadboost_agency) по просьбе владельца есть только там, на кнопки их
  не добавлять; их значки тоже прислал владелец (у TikTok взята только
  белая нота, без голубого и красного слоя). Все пять файлов одного
  формата: форма вписана по высоте во всю картинку. Ник @leadboost_agency
  на кнопках и в подвале не пишем, только название соцсети.
- Стрелки, галочки, крестики только SVG (`icons.jsx`): в подмножествах
  веб-шрифтов нет символов → ↗ ✓ ✕. Крестики на лентах рисует CSS-маска
  (`.tape-word::after`, цветом текста ленты), чтобы не плодить десятки
  SVG в разметке.
- Движение сдержанное: мазок-плашка тянется слева направо при появлении и
  ленты. Приветствия с бегущими буквами (scramble) и счёта 240+/310% от
  нуля больше нет (ноябрь 2026): типичные эффекты готовых лендингов,
  цифры сразу на месте. Всё отключается при
  prefers-reduced-motion. При наведении карточки и кнопки только меняют
  цвет или обводку, не подпрыгивают (ноябрь 2026, unslop). Бесконечных
  вращений нет, жёлтого пятна за курсором (`.spotlight`) больше нет.
- Жёлтая плашка в заголовке на композицию одна: бейджи «основное» у
  услуги и «рекомендую» у тарифа $290 (`.badge.main`) обведены цветом
  `--accent`, а не залиты жёлтым; «дополнительно» обведено серым.
- Карточки (плитки с рамкой) только там, где их сравнивают или они
  несут цифру: первый экран, услуги, ниши, кейсы, скрины, тарифы,
  форма. «Как я работаю», «Кому подходит» и «Вопросы»
  простыми списками с тонкими линиями 2px (ноябрь 2026: когда в рамке
  всё, рамка ничего не выделяет). Иконки в квадратиках только у четырёх
  услуг; у ниш и принципов их нет.
- Все кнопки связи (WhatsApp, Telegram, Instagram) капсом Oswald, как
  остальные кнопки. Раньше WhatsApp был капсом, а Telegram и Instagram
  обычными буквами.

Базовый размер некрупного текста не ниже ~14.5px (просьба пользователя
«чтобы посетители не мучали глаза»), не занижать при правках.

## Контент: только реальное

- Кейсы (с 15 ноября 2026 один раздел #results «Кейсы из моего кабинета
  Meta», в меню «Кейсы»; отдельного раздела #work больше нет). Шесть
  кейсов из отчётов владельца по каждому скрину (его Google Сайт
  «Портфолио рекламных кейсов (NDA Edition)»): ниша, город, срок, цифра,
  скрин, «Что было» и три шага «Что сделал», бренды скрыты по NDA. Данные в
  `CASES` (data.jsx, три языка), карточки две в ряд, строки выровнены
  subgrid. Тексты переписаны от первого лица и проще, цифры как у
  владельца; цифры «до» (например «от $0,95 до $1,20», «до 45%», «80%
  диалогов») владелец должен подтвердить до публикации. Ниже «Ещё
  результаты» (`MORE`): онлайн-школа −61% цены заявки, магазин $1 500 за
  5 дней (подтверждены владельцем, без скринов) и трафик в Instagram со
  скринами по кнопке. 240+ кампаний и средний ROAS 310% на первом экране.
  Скрины 142 переписки по $0,61, 11 по $1,64 и две B2B-кампании (37 по
  $5,06, 17 по $4,29) владелец прислал без отчётов, на сайт не ставили.
  Полосы «Скоро: первый сайт-проект» больше нет: первый сайт добавить
  настоящим кейсом.
- Блок «С кем работаю» (#niches, отдельная секция после услуг): 8 ниш
  плитками 3×3 без иконок, со строкой «что приводит реклама» (`NICHES` в
  data.jsx: `label`, `desc`), девятая жёлтая плитка «Твоей ниши нет?»
  ведёт в WhatsApp. Строки `desc` описывают цель рекламы в нише, а не
  результаты: не превращать их в обещания цифр.
- В форме заявки у полей «Что интересует» и «Чем занимаешься» последний
  пункт «Другое» (ниши формы в `NICHE_DATA`, «Другое» добавлено в самой
  форме).
- Первое поле формы «Тариф» (просьба владельца, ноябрь 2026): список из
  `PLANS` с ценой в месяц и пункт «Пока не знаю, нужен совет». Это тот же
  выбор, что ставит кнопка «Выбрать» в тарифах (`planStore`), поэтому при
  смене тарифов в data.jsx список меняется сам. В Telegram уходит название и
  цена тарифа на русском или «не выбрал, нужен совет».
- Мини-игры больше нет (ноябрь 2026: одна из самых частых «фишек»
  сгенерированных лендингов, шутки спорили с правилом «без юмора и игровых
  мотивов»). Её приз, бесплатный разбор, теперь прямым предложением в
  «Контакте» над кнопками связи (`contact.offer` в i18n.jsx): «Уже есть
  реклама? Пришли скрин своего рекламного кабинета, бесплатно скажу, что бы
  поправил». Мишени (кольца с точкой) на сайте нет нигде (брендбук).
- Бейдж среднего тарифа «Рекомендую» (раньше «Выбор большинства»: это нельзя
  было подтвердить, владелец выбрал замену, ноябрь 2026).
- Тарифы (решение владельца 16.11.2026, прежние $170 / $290 / $490
  выглядели слишком дёшево): Базовый $350, Оптимальный $550, Премиум $850 в
  месяц, разовой оплаты за запуск нет. Уровень взят из внутреннего прайса

  (порог такой, чтобы 12% не было дешевле тарифов: при $3 000 вышло бы
  $360). Меняя цены, менять и `seo.js` (description «от $…»).

## Важные технические решения (не переделывать не глядя)

1. **Картинки только через `asset("img/...")` (src/assets.js).** Раньше
   логотип был base64 внутри JS (из-за бага с относительным путём от
   `dist/`), это утяжеляло и скрипт, и готовый HTML. Теперь логотип и
   иконки лежат файлами в `img/`, путь абсолютный от корня (`/img/...`),
   поэтому работает и на `/kk/`, и на `/en/`. В превью-артефакте
   index.html задаёт `window.LB_BASE = "./"`; assets.js один раз при
   загрузке превращает его в полный адрес. Иначе после смены языка адрес
   страницы становился /en/, и иконки услуг искались в /en/img/... (битые
   картинки в превью, октябрь 2026).

2. **Шрифт Cook Conthic (`src/fonts/`) больше не подключён.** Цены и
   wordmark теперь в Oswald, как на каруселях. Файлы лежат на случай
   отката; в нём нет кириллицы, к русскому тексту его не применять.

3. **Крупные цифры (кейсы, скрины, тарифы) в Oswald.** У Oswald цифры
   пропорциональные и нет tnum, поэтому для меняющихся на глазах чисел он
   не подходит: такие числа (их было в калькуляторе, убран в ноябре 2026)
   ставить в JetBrains Mono, там они не прыгают. `useTween` в hooks.jsx
   остался на этот случай.

4. **Премиум-иконки** из купленного Envato-пака «65 Marketing Agency Line
   Icons» (компоненты в icons.jsx, исходно мультицветные, пересобраны в
   `currentColor`). На странице 4 из них (услуги) отдаются
   файлами `img/icons/premium/*.svg` (так они не раздувают JS и HTML), но
   рисуются CSS-маской (`.prem-ic`, `--ic: url(...)`) цветом `--accent`:
   чёрные в светлой теме, жёлтые в тёмной. Сами файлы жёлтые, их цвет
   не важен. В data.jsx у услуг `icon: "ads"` и т.п. (у принципов иконок
   больше нет, их файлы удалены).
   Высокая детализация: **не уменьшать меньше ~36-46px**.

5. **html/body фон = `#FAFAF7`, в тёмной теме `#0F1216`** задан отдельно от
   `.cl-root` (и в index.html), без этого при овербаунс-скролле (трекпад
   macOS) видно фон браузера другого цвета.
   В index.html есть общий сброс `*{margin:0;padding:0}`: из-за него у
   `<dialog>` явно стоит `margin: auto`, иначе окно прилипает к верху.

6. **Telegram-форма отправляется через серверную функцию `api/telegram.js`**
   (Vercel), не напрямую из клиента. Токен и chat_id — переменные окружения
   `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` на Vercel (Settings →
   Environment Variables), их больше нет в `src/config.js` и в бандле
   `dist/main.js` — проверено grep'ом по собранному файлу. Локально в
   `npm run dev` (esbuild --servedir) функция `/api/*` не выполняется —
   это работает только через Vercel (прод или `vercel dev`), поэтому в
   локальной разработке форма ожидаемо показывает ошибку со ссылкой на
   WhatsApp (запасной канал вместо прежнего mailto). В заявку уходит и
   тариф, если человек нажал «Выбрать» в тарифах.

7. **Статус «на связи» считается по часовому поясу владельца**
   (`WORK_TZ = "Asia/Baku"` в config.js), а не посетителя.

8. **Диагностика в index.html** показывает экран ошибки только если не
   загрузились скрипт или стили. Незагрузившаяся картинка (скрин) только
   пишет предупреждение в консоль.

9. **Готовый HTML + hydrate: правила, чтобы не было расхождений.**
   HTML собирается заранее (scripts/build-site.mjs через src/prerender.jsx),
   браузер его «оживляет» (hydrateRoot). Поэтому первый рендер не должен
   зависеть от времени, случайных чисел, window/localStorage: всё такое
   только после монтирования (`useMounted`, эффекты). Пример: статус «на
   связи» скрыт (`.pending`) до запуска в браузере. Проверка: в консоли браузера не должно быть
   ошибок hydration.

10. **Части страницы оживают по отдельности** (`<Part>` = `<Suspense>`
   вокруг секций после первого экрана): нет одного долгого блокирующего
   куска JS после загрузки. Следствие: ref на элемент внутри Part нельзя
   держать в хуке App (элемент появится позже эффекта App). Хук и ref в
   одном компоненте, как у `Tape` с `useVelocityMarquee`.

11. **Стили встраиваются в HTML при сборке** (`<style>` вместо ссылки на
   CSS), шрифты первого экрана (Oswald и Inter) подгружаются заранее
   (`preload`). JS и CSS в `public/assets/` с хэшем в имени и кэшем на год
   (`vercel.json`).

12. **App хранит только язык, каждая секция — свой компонент со своим
   состоянием** (`Services` открытая услуга, `Results` открытый скрин,
   `Faq`, `Contact` форма). Раньше всё состояние жило в App:
   каждое событие скролла перерисовывало всю страницу, а клик или смена
   языка, пока часть секций ещё оживала (п. 10), давали ошибку React #421
   в консоли и выбрасывали готовый HTML этих секций. Теперь:
   - скролл обновляет только `NavProgress` (полоска) и `FloatingCta`
     (`useScrollProgress` / `useScrolledPast` в interactions.jsx);
   - статус «на связи» считается внутри `Hero` и `Footer`;
   - тариф из «Выбрать» передаётся в форму через маленькое хранилище
     `planStore` (useSyncExternalStore), а не через состояние App;
   - смена языка идёт через `startTransition` (useLang в i18n.jsx).
   Проверка: быстрый скролл, клик и смена языка сразу после загрузки на
   медленном процессоре (×8) не дают ошибок в консоли. Не возвращать
   состояние секций в App.

13. **Выравнивание строка в строку через CSS subgrid** (Кому подходит,
   Тарифы, только на ширине, где колонки стоят рядом): заголовки, пункты
   списков и кнопки соседних колонок на одном уровне. В «Кому подходит»
   число строк задаёт App.jsx через `--fit-rows` (по длинному списку). В
   браузере без subgrid колонки просто не выровнены. «Как я работаю» с
   ноября 2026 список строк (слева принцип, справа текст), subgrid там не
   нужен. Сетка ниш: все ряды одной высоты (`grid-auto-rows: 1fr`), на
   телефоне 2 колонки, уже 360px по одной.

14. **Шапка: логотип никогда не сжимается, на телефоне меню.** Раньше на
   телефонах содержимое «пилюли» было шире неё: в Chrome переключатель
   языка вылезал за край, а Safari на iPhone ужимал картинку логотипа до
   нуля (логотип «пропадал»). Теперь у логотипа точный размер и
   `flex-shrink: 0`. Компьютер (от 761px): «пилюля» по центру, логотип
   121×17, четыре ссылки (с 15.11.2026, было пять), кнопка темы 36px, язык (`.nav-tools`). Телефон и
   планшет (до 760px): полоса во всю ширину, логотип 114×16 (до 330px
   100×14), справа кнопка темы 40px, язык и кнопка меню (уже 320px кнопка
   темы в полосе прячется, остаётся строка в меню)
   (`.burger`), ссылки в панели `MobileMenu`: шесть разделов с номерами,
   кнопки WhatsApp, Telegram и Instagram; закрывается по выбору пункта, нажатию
   мимо, Esc и при расширении окна, страница под ней не прокручивается.
   Панель стоит вне `<nav>`: у навбара transform и backdrop-filter, внутри
   него position: fixed считался бы от навбара, а не от экрана. Проверено
   скриптом на ширинах от 280 до 1440px на трёх языках: логотип не меньше

15. **Солнце и луна в переключателе темы — формы Lucide** (lucide.dev,

## Сборка

```bash
npm install
npm run dev         # разработка, автопересборка, http://localhost:8000 (рендер в браузере)
npm run build       # сборка в dist/ для локального просмотра index.html (npx serve .)
npm run build:site  # готовый сайт в public/: то же, что делает Vercel
```

Деплой (Vercel): настройки в `vercel.json`. Vercel запускает
`npm run build:site` (scripts/build-site.mjs) и публикует `public/`:
готовые `/`, `/kk/`, `/en/`, `assets/` с хэшами, `img/`, robots.txt,
sitemap.xml, site.webmanifest, favicon.ico, 404.html. Функция
`api/telegram.js` подхватывается из корня автоматически. Адрес сайта для
canonical и sitemap берётся из `SITE_URL` или из системной переменной
Vercel `VERCEL_PROJECT_PRODUCTION_URL` (свой домен подхватится сам при
следующей сборке). Раньше каждый деплой падал с `No Output Directory named
"public"` (так было со всеми коммитами с августа 2026). `public/`, `dist/`,
`.build/` в .gitignore, не коммитить. Проверить сборку как на Vercel
локально: `npx vercel build` (нужен `.vercel/project.json`).
