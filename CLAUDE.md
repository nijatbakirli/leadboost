# LeadBoost — контекст проекта

Лендинг бренда LeadBoost (Nijat, Баку). Основная услуга — таргетированная
реклама, дополнительная — создание сайтов. Клиенты преимущественно в
Казахстане, цены в USD.

## Дизайн: как в каруселях LeadBoost (с октября 2026)

Сайт оформлен в том же стиле, что и Instagram-карусели и обложки Reels
LeadBoost (Figma-файл каруселей d395dvUXTP40ey4jbBBLfR). Прежний
ruslik-необрутализм (Hanken Grotesk, #101014, неоновые кружки с номерами
секций, ноутбук в хиро) полностью заменён, он остался только в истории git.

- Фон `#0F1216` с сеткой 60px (белый 5.5%), плитки `#151A21`, обводка 2px
  `#232A33`, радиус 28 (на телефоне 22), внутренние блоки `#1E242D`.
- Жёлтый `#F0E60D`, текст на жёлтом `#0F1216`. Тело `#D3D9E2`, вторичный
  `#AEB7C3`, тусклый `#8A94A1`.
- Шрифты: **Oswald Bold** капсом (заголовки, крупные цифры, кнопки),
  **Inter Medium** (текст), **JetBrains Mono Bold** (лейблы `// ТЕКСТ`,
  бейджи, цифры калькулятора). Свои файлы через пакеты `@fontsource/*`
  (импорт в main.jsx), без Google Fonts: быстрее и без внешних запросов.
- Заголовок секции = компонент `<Heading pre mark>`: строки `pre` белым,
  последняя строка `mark` на жёлтой плашке (`.hl`). Плашка обрезана по
  высоте как на каруселях: 13px над капителью и 10px под базовой линией
  при 104px (в CSS это 1.031em, смещение 0.258em). Перед строкой с плашкой
  отступ 0.16em, чтобы строки не слипались.
- Лейбл секции = `<SecLabel>`: моно `// ТЕКСТ` (#E9EDF2, в плитках #9AA4B2).
- Первый экран: угловые жёлтые скобки 50×4 / 4×50, бенто-сетка (заголовок,
  реальная цифра из кабинета со скрином, 240+ кампаний, ROAS 310%).
- Под первым экраном перекрещённые ленты (жёлтая −3°, белая +2.5°), едут
  в разные стороны (`useVelocityMarquee`), как на обложке Reels.
- Футер: «LEADBOOST ├────┤ НАПИСАТЬ →» как подпись на каруселях.
- Стрелки, галочки, крестики только SVG (`icons.jsx`): в подмножествах
  веб-шрифтов нет символов → ↗ ✓ ✕. Крестики на лентах рисует CSS
  (`.tape-word::after`), чтобы не плодить десятки SVG в разметке.
- Движение сдержанное: плашка «наезжает» при появлении, scramble в
  приветствии, счётчик 240+/310%, ленты. Всё отключается при
  prefers-reduced-motion.

Базовый размер некрупного текста не ниже ~14.5px (просьба пользователя
«чтобы посетители не мучали глаза»), не занижать при правках.

## Контент: только реальное

- Кейсы: онлайн-школа −61% цены заявки, магазин $1 500 за 5 дней,
  240+ кампаний, средний ROAS 310% (подтверждено владельцем).
- Клиника ×4.1 и все цитаты клиентов удалены: они не были реальными.
  Не возвращать и не придумывать новые.
- Секция «Цифры из кабинета» (#results): настоящие скрины Meta Ads Manager
  в `img/results/*.webp`. Обрезаны края, превью креативов клиентов
  размыты, цифры и цвета не трогались (скрипт обработки в истории чата).
  Данные и подписи в `RESULTS` в data.jsx, клик открывает скрин крупно
  (`ShotViewer`, нативный `<dialog>`).
- Русский текст на «ты», без длинных тире (—). Казахский оставлен на «сіз»
  (машинный перевод, проверить носителем). Английский нейтральный.

## Структура кода (чистая архитектура, НЕ смешивать обратно в App.jsx)

```
src/
├── main.jsx          — точка входа в браузере (hydrate готового HTML или рендер с нуля)
├── prerender.jsx     — точка входа для сборки HTML в Node (в браузер не попадает)
├── App.jsx           — ТОЛЬКО композиция и разметка, без контента/конфига
├── config.js          — настройки владельца (контакты WhatsApp/Instagram, места, часы работы)
├── data.jsx            — ВЕСЬ контент по языкам: CONTENT.{ru,kk,en}
├── i18n.jsx             — UI-строки интерфейса по языкам (UI.{ru,kk,en}) + useLang
├── seo.js               — адреса языков, title/description/OG, JSON-LD
├── assets.js            — asset(): путь к картинкам ("/" на сайте, "./" в превью)
├── interactions.jsx    — императивные хуки (scroll, cursor, ленты, статус «на связи»)
├── hooks.jsx            — базовые хуки (useReveal, Reveal, useTween)
├── widgets.jsx          — Scramble, CountMetric, Mark, SecLabel, Heading, TargetGame, ShotViewer
├── icons.jsx             — SVG-иконки интерфейса (стрелки, галочки, ниши)
├── styles.css            — все стили одним файлом
├── logo.png              — исходник логотипа (на сайте используется img/logo.webp)
└── fonts/               — CookConthic (больше не используется)
img/
├── logo.webp / logo.png  — логотип для навбара и разметки
├── icons/               — favicon, иконки 192/512, apple-touch-icon,
│   └── premium/         — крупные иконки услуг и принципов (SVG, жёлтые)
├── og/og-{ru,kk,en}.jpg  — картинки для превью ссылок 1200×630
└── results/             — скрины из рекламного кабинета (WebP)
scripts/build-site.mjs   — сборка готового сайта в public/ (то, что запускает Vercel)
```

Правки текста/цен/тарифов — только в `data.jsx` (менять во всех трёх
языковых блоках сразу: ru/kk/en). Правки UI-надписей (кнопки, лейблы,
футер) — в `i18n.jsx`. Правки токенов/лимитов — только в `config.js`.
Не хардкодить контент обратно в JSX разметку.

**Многоязычность (RU/KZ/EN)**: у каждого языка свой адрес: `/` русский,
`/kk/` казахский, `/en/` английский, у каждого свой готовый HTML с
`lang`, title, description, canonical и hreflang (нужно для поиска).
Переключатель в навбаре: настоящие ссылки на эти адреса, но клик меняет
язык без перезагрузки и адрес через history.pushState; кнопка «назад»
возвращает язык. localStorage для языка больше не используется.
Заявка в Telegram всегда на русском независимо от языка сайта (её читает
владелец, не посетитель): см. `RU = CONTENT.ru` в `App.jsx`. Казахский
текст: машинный перевод, не вычитан носителем, стоит проверить.

**SEO (октябрь 2026)**: готовый HTML для поисковиков и превью ссылок
(без него поисковики без JS и мессенджеры видели пустую страницу),
мета-теги и Open Graph с картинками на трёх языках, JSON-LD (Organization,
WebSite, WebPage, Service с тремя тарифами, FAQPage), robots.txt,
sitemap.xml с hreflang, favicon и иконки, 404.html. Ключевые слова в
title/description и в тексте: таргетированная реклама, Instagram, Facebook,
Казахстан, СНГ, Алматы, Астана (вопрос в FAQ про география). Lighthouse
(телефон, со сжатием): производительность 93-97, SEO, доступность и best
practices по 100. Картинки превью `img/og/*.jpg` статичные: если меняется
главный заголовок, их нужно перерисовать.

## Важные технические решения (не переделывать не глядя)

1. **Картинки только через `asset("img/...")` (src/assets.js).** Раньше
   логотип был base64 внутри JS (из-за бага с относительным путём от
   `dist/`), это утяжеляло и скрипт, и готовый HTML. Теперь логотип и
   иконки лежат файлами в `img/`, путь абсолютный от корня (`/img/...`),
   поэтому работает и на `/kk/`, и на `/en/`. В превью-артефакте
   index.html задаёт `window.LB_BASE = "./"`.

2. **Шрифт Cook Conthic (`src/fonts/`) больше не подключён.** Цены и
   wordmark теперь в Oswald, как на каруселях. Файлы лежат на случай
   отката; в нём нет кириллицы, к русскому тексту его не применять.

3. **Цифры калькулятора в JetBrains Mono** намеренно: при пересчёте
   (useTween) моноширинные цифры не прыгают. Крупные статичные цифры
   (кейсы, скрины, тарифы) в Oswald. У Oswald цифры пропорциональные и
   нет tnum, поэтому для анимированных счётчиков в таблицах он не подходит.

4. **Премиум-иконки** из купленного Envato-пака «65 Marketing Agency Line
   Icons» (компоненты в icons.jsx, исходно мультицветные, пересобраны в
   `currentColor`). На странице 8 из них (услуги и принципы) отдаются
   файлами `img/icons/premium/*.svg` уже в жёлтом #F0E60D: так они не
   раздувают JS и HTML. В data.jsx у услуг/принципов `icon: "ads"` и т.п.
   Высокая детализация: **не уменьшать меньше ~36-46px**.

5. **html/body фон = `#0F1216`** задан отдельно от `.cl-root` (и в index.html),
   без этого при овербаунс-скролле (трекпад macOS) видно белый фон браузера.
   В index.html есть общий сброс `*{margin:0;padding:0}`: из-за него у
   `<dialog>` явно стоит `margin: auto`, иначе окно прилипает к верху.

6. **Telegram-форма отправляется через серверную функцию `api/telegram.js`**
   (Vercel), не напрямую из клиента. Токен и chat_id — переменные окружения
   `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` на Vercel (Settings →
   Environment Variables), их больше нет в `src/config.js` и в бандле
   `dist/main.js` — проверено grep'ом по собранному файлу. Локально в
   `npm run dev` (esbuild --servedir) функция `/api/*` не выполняется —
   это работает только через Vercel (прод или `vercel dev`), поэтому в
   локальной разработке форма ожидаемо показывает ошибку со ссылкой на
   WhatsApp (запасной канал вместо прежнего mailto). В заявку уходит и
   тариф, если человек нажал «Выбрать» в тарифах.

7. **Статус «на связи» считается по часовому поясу владельца**
   (`WORK_TZ = "Asia/Baku"` в config.js), а не посетителя.

8. **Диагностика в index.html** показывает экран ошибки только если не
   загрузились скрипт или стили. Незагрузившаяся картинка (скрин) только
   пишет предупреждение в консоль.

9. **Готовый HTML + hydrate: правила, чтобы не было расхождений.**
   HTML собирается заранее (scripts/build-site.mjs через src/prerender.jsx),
   браузер его «оживляет» (hydrateRoot). Поэтому первый рендер не должен
   зависеть от времени, случайных чисел, window/localStorage: всё такое
   только после монтирования (`useMounted`, эффекты). Пример: приветствие
   в готовом HTML всегда «Добрый день», статус «на связи» скрыт (`.pending`)
   до запуска в браузере. Проверка: в консоли браузера не должно быть
   ошибок hydration.

10. **Части страницы оживают по отдельности** (`<Part>` = `<Suspense>`
   вокруг секций после первого экрана): нет одного долгого блокирующего
   куска JS после загрузки. Следствие: ref на элемент внутри Part нельзя
   держать в хуке App (элемент появится позже эффекта App). Хук и ref в
   одном компоненте, как у `Tape` с `useVelocityMarquee`.

11. **Стили встраиваются в HTML при сборке** (`<style>` вместо ссылки на
   CSS), шрифты первого экрана (Oswald и Inter) подгружаются заранее
   (`preload`). JS и CSS в `public/assets/` с хэшем в имени и кэшем на год
   (`vercel.json`).

## Сборка

```bash
npm install
npm run dev         # разработка, автопересборка, http://localhost:8000 (рендер в браузере)
npm run build       # сборка в dist/ для локального просмотра index.html (npx serve .)
npm run build:site  # готовый сайт в public/: то же, что делает Vercel
```

Деплой (Vercel): настройки в `vercel.json`. Vercel запускает
`npm run build:site` (scripts/build-site.mjs) и публикует `public/`:
готовые `/`, `/kk/`, `/en/`, `assets/` с хэшами, `img/`, robots.txt,
sitemap.xml, site.webmanifest, favicon.ico, 404.html. Функция
`api/telegram.js` подхватывается из корня автоматически. Адрес сайта для
canonical и sitemap берётся из `SITE_URL` или из системной переменной
Vercel `VERCEL_PROJECT_PRODUCTION_URL` (свой домен подхватится сам при
следующей сборке). Раньше каждый деплой падал с `No Output Directory named
"public"` (так было со всеми коммитами с августа 2026). `public/`, `dist/`,
`.build/` в .gitignore, не коммитить. Проверить сборку как на Vercel
локально: `npx vercel build` (нужен `.vercel/project.json`).
