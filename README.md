# LeadBoost: лендинг

## Структура

```
leadboost/
├── index.html          — шаблон страницы (в разработке рисуется в браузере,
│                          при сборке сайта в него вписывается готовый HTML)
├── package.json        — зависимости и скрипты
├── vercel.json         — настройки сборки, кэша и редиректов на Vercel
├── api/
│   └── telegram.js     — серверная функция (Vercel): форма → Telegram,
│                          токен только тут, как переменная окружения
├── scripts/
│   └── build-site.mjs  — сборка готового сайта в public/ (её запускает Vercel)
├── src/                — исходники (чистая архитектура)
│   ├── main.jsx        — точка входа в браузере
│   ├── prerender.jsx   — точка входа для сборки готового HTML
│   ├── App.jsx         — композиция и разметка: каждая секция — свой компонент
│                          со своим состоянием, App хранит только язык
│   ├── config.js       — НАСТРОЙКИ ВЛАДЕЛЬЦА: WhatsApp/Instagram, места, часы работы
│   ├── data.jsx        — ВЕСЬ КОНТЕНТ: тексты, тарифы, кейсы, скрины, FAQ
│   ├── i18n.jsx        — надписи интерфейса на трёх языках
│   ├── seo.js          — title, description, превью ссылок, разметка для поиска
│   ├── assets.js       — путь к картинкам
│   ├── interactions.jsx— вся императивная логика (хуки с JSDoc)
│   ├── styles.css      — все стили
│   ├── icons.jsx       — SVG-иконки
│   ├── hooks.jsx       — базовые хуки (useReveal / Reveal / useTween)
│   └── widgets.jsx     — заголовки с плашкой, счётчики, мини-игра, просмотр скринов
├── img/                — логотип, иконки, картинки превью ссылок, скрины из кабинета
└── docs/
    └── CODE_REVIEW.md  — отчёт код-ревью
```

## Запуск

**Локально:**
```bash
npm install
npm run build     # сборка в dist/
npx serve .       # откройте выданный адрес
```

**Разработка (правки кода):**
```bash
npm install
npm run dev         # http://localhost:8000, автопересборка
npm run build:site  # готовый сайт в public/, как на Vercel
```

## Публикация (Vercel)

1. Импортировать GitHub-репозиторий в Vercel (New Project → выбрать репо).
2. В настройках проекта: Settings → Environment Variables → добавить
   `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (значения — из @BotFather и
   `getUpdates`, см. историю переписки/чата). Без них форма отправки
   вернёт ошибку 500 — это единственное место, где токен теперь хранится.
3. Deploy: настройки сборки уже лежат в `vercel.json`. Vercel запустит
   `npm run build:site` (готовые страницы `/`, `/kk/`, `/en/`, robots.txt,
   sitemap.xml в `public/`) и подхватит папку `api/` как серверные функции.
   Слияние в `main` публикует сайт в продакшн.
4. После первой публикации: добавить сайт в Google Search Console и
   Яндекс Вебмастер и отправить там `https://<домен>/sitemap.xml`.
   Свой домен подключается в Vercel (Settings → Domains), адрес в canonical
   и sitemap обновится сам при следующей сборке.

Локально (`npm run dev`) папка `api/` не выполняется — esbuild это просто
статический сервер, серверные функции работают только на Vercel (или через
`vercel dev`, если он установлен). Форма в dev-режиме покажет ошибку со
ссылкой на WhatsApp, это ожидаемо, не баг.

## Перед запуском — src/config.js

1. `CONTACTS`: ссылки на WhatsApp и Instagram
2. `SPOTS_LEFT`: честное число свободных мест
Тексты, цены и подписи к скринам правятся в `src/data.jsx`, надписи интерфейса в `src/i18n.jsx`.
